# SlotBack — Working Context and Changelog

> This file is the project's concise progress ledger and handoff context for AI agents. Stable rules live in `AGENTS.md`; product and technical contracts live in `docs/`.

## Product context
SlotBack helps small service businesses recover appointment capacity lost to cancellations by offering released slots to eligible waitlisted customers. The core value is reliable recovery, fewer manual coordination steps and measurable outcomes—not a decorative dashboard or an unnecessary AI feature.

## Stack decisions
- Single-Server Production Architecture: FastAPI serves both REST API (`/api/v1/*`) and compiled React SPA (`frontend/dist`).
- Frontend: React 18 + TypeScript + Vite + Vanilla CSS design system.
- Backend: Python 3.12+, FastAPI, Pydantic v2.
- Database: PostgreSQL (`slotback` database).
- ORM/migrations: SQLAlchemy 2.x + Alembic (`5910adfcb702_initial_schema`).
- PostgreSQL driver: psycopg 3.
- Testing: pytest, FastAPI TestClient, PostgreSQL integration tests, Vite production bundle build.
- API prefix: `/api/v1`.
- OpenAPI: generated by FastAPI at `/docs`.

## Product invariants
- A released slot cannot be claimed by more than one confirmed booking.
- Expired, withdrawn or consumed offers cannot be accepted.
- Customers cannot access another customer's protected records.
- Notification failure must not silently falsify booking status.
- Metrics must be computed from persisted events/records with documented denominators.
- No production metric, test result or deployment claim is valid without evidence.
